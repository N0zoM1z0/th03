# MAIN Chiyuri — large natural Turbo C++ producer, after559

The Chiyuri boss source is not a stub or a collection of leaf functions.
Its maintained natural C++ TU in src/main/boss/chiyuri.cpp contains
**11 complete functions**, including the **613-byte boss update controller**
and **528-byte multi-pattern fan attack routine**. The entire native producer
is **2,654 CODE bytes**, including its **81-byte compiler-generated switch
table**. The original code location is decoded MAIN load-image
0x1219D..0x12BFB, native segment 0F1F:2FAD.

## Disproved previous probe assumption

The historical local function-shape probe appended a global **-a2** Turbo C++
compiler option that is absent from the actual original MAIN cold link.
The maintained C++ source already contains a separate **local** packing
pragma around the Chiyuri character template; adding -a2 to the entire
compiler invocation alters the storage layout assumed for the bullet
template included from the original ReC98 context.

The wrong global option still yielded all 11 correct instruction shapes and
the expected 81-byte switch table. However, substituting that OBJ into the
real MAIN link produced **36 changed bytes** in the Chiyuri CODE: 25
one-byte address advances and 11 two-byte advances in the mutable bullet
template member references. The complete native EXE was not equal, despite
its identical 1,553-entry relocation list and MAP geometry. This is proof
that the earlier shape-only PASS could not justify original byte equality.

The probe now uses the **actual native first-use TCC flags**:

    -c -I. -O -b- -3 -Z -d -DGAME=3 -ml

Removing the incorrect global -a2 (while retaining the natural source-local
packing pragma) made the emitted original OBJ **identical after narrow
dependency-timestamp normalization**. This compares the complete raw OMF
structure and initializer/fixup/public packets, not just the decoded
instruction lengths.

scripts/build_th03_main_boss_chiyuri_after559_work.py builds the genuine
maintained C++ TU in **two independent source materializations** using Turbo
C++ 4.02. Each produced OBJ has exactly the original 2,654-byte native
payload, 11 entrypoints and true 81-byte switch table. Each is substituted
into only the old Chiyuri object slot of the frozen original 99-object MAIN
link response. No full cold replay or rebuild of other game objects occurs.

Both normal TLINK runs reproduced the **entire retained 132,322-byte native
MAIN EXE** and **its complete 157,164-byte MAP** exactly. Both also retained
all **1,553 original ordered MZ relocation entries**, and the entire
Chiyuri 2,654-byte decoded owner agrees with the pinned Japanese target.

stage does not promote whole-game or Factory acceptance. Chiyuri is
