# Experimental central round-loop source

This checkpoint preserves complete natural source for the central gameplay loop
and its genuine score-transfer dependency. **Zero exactness credit.** Neither
source is activated in the accepted linker graph or exact-unit/function ledgers.
No whole-game completion percentage follows from these experiments.

## Complete target scope and ABI

The loop is one function at MAIN load **9778..9AD6**, 862 bytes and 247
instructions, with four near returns: 9972=AL2, 99A7=AL1, 99B0=AL2, 9AD5=AL0.
It has no table, local stack allocation or SI/DI save. It includes gameplay,
collision/input, every render pass, defeat/result handling, both background/demo
callbacks, page/vsync sequencing, counters and difficulty changes.

The complete near Pascal helper at **A289..A2D0** is 71 bytes/29 instructions
and ends RET2. Its word winner argument selects one of two eight-digit scores.
Each iteration copies that player's digit to the same resident slot and zeros
the opposite resident slot. The two loop exits are its only observed callers.
The caller discards any residual register contents and returns its own AL2.

These are **noncontiguous target ranges**. The intervening 9AD6..A289 code is
not generated by this file. Combining both bodies in a packed compiler object
tested a real dependency hypothesis; it did not establish the original TU or
physical placement. Existing historical allocation remains external.

The byte at DS:6590 is one union, used as current player 0/1 or attack offset
0/40. It cannot become two variables. Callback slots are far pointers in
DGROUP except two near background/demo pointers. Round-frame storage is
32-bit; the round/result counter is 16-bit. Existing owning headers supply
difficulty, defeat, palette and player/resident types; assertions pin their
observed widths/fields. Real PC-98 OUT operations and the BX VRAM helper ABI
are retained. The show-page OUT preserves AL, which C++ assigns to page_front.

## Three bounded native experiments

1. Standalone v01 compiled successfully to 862 CODE bytes, with one public and
   no storage. This size match was coincidental. The compiler merged the two
   score-transfer/AL2 exits, and an unnecessary page-back reload added bytes.
   Only three RETs were emitted.
2. Standalone v02 restored target lexical block order and used the real
   post-OUT AL value. It produced 857 CODE bytes. The remaining difference is
   one compiler common-tail merge: the target's seven-byte CALL A289 / MOV AL,2 /
   POP BP / RET at 996C becomes a two-byte jump to the shared game-over tail.
   Thus five bytes and one independent return site remain missing.
3. A single same-TU experiment appended the complete genuine helper after the
   unchanged v02 loop. It produced 928 CODE bytes: loop857 + helper71. The loop
   changed only its actual local call displacement; the tail merge persisted.
   This hypothesis is negative and closed. No further variations or flag sweep
   were run.

All three were one-compiler-invocation, one-CPU/nice10, bounded compile-only
experiments. Their input, HEAD, dirty-state and mode guards passed, as did owned
process cleanup. No native link, replay, byte patch, padding, fake alias,
empty barrier, injected side effect or fabricated ABI was used.

## Limits of the comparisons

The v02 diagnostic matched 31 local branch destinations under the five-byte
layout mapping and 443 non-fixup/non-branch bytes. The helper matched 65 of 65
non-fixup bytes; three word DGROUP operands remain linker obligations. These
are deliberately **exclusion-based diagnostics, not raw byte equality**.
The helper experiment has 164 real OMF fixups and packed publics at 0/857.
No original ordered MZ, MAP or cold-link acceptance has been established.

The independent review also confirmed call-boundary near/far/Pascal contracts.
Neutral dependency names remain for unresolved behaviors. In particular D52E
is not merely rendering: it can increment resident story_lives, call BA5B and
alter DS:4B7C. CEB2/CEE0 update/consume twelve ten-byte records at DS:3946.

## Integration remains blocked

Preserve the 16 ordered target loop MZ records in the evidence JSON and every
accepted owner's original gates. The loop is interior to PLAYFLD_TEXT: its
0x98-byte prefix and following suffix cannot simply be concatenated before an
added producer. Any future carve needs reviewed original group/segment ordering,
all external storage/call aliases, seven genuine same-group far-call relaxations,
outside-scope byte preservation and two complete cold-link Oracles.

Source names are not necessarily linker names: Pascal symbols are uppercase
and long C names can truncate. The bindings proposal includes actual EXTDEF and
PUBDEF names. It does not define aliases or allocate storage.
