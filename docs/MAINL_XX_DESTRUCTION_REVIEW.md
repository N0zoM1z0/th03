The78-byte prefix contains two catch-all handler tables and their nested
try/catch contexts. Both terminate-on-exception scopes are retained as natural
C++ `try/catch`; their data are generated by the compiler. The review independently
resolves all2500 original bytes from the original xx OMF member and normal-library
MAP,including19 fields in literal emission order,five literal ordered MZ segment
WORD sites and real far-call relaxation. Each function is densely decoded through
its actual return; direct branches land on instructions. Ghidra's previous body
spans were hypotheses until these checks. The decoded database was independently
re-attested against the fixed Japanese target before its observations were used.

The packed ABI prefix uses38-byte type descriptors,8-byte base entries,6-byte
member entries and10-byte destructor-table entries. Global and registration
destructor counts are DWORDs; class total/nonvirtual counts at+1A/+1C are WORDs.
Array descriptors store a DWORD element length,but these paths consume its low
WORD. BCC's `__RefDestructorCount()` intrinsic returns the address of the SS:10
DWORD; it is dereferenced before subtraction. The empty-table test compares
only the far pointer's low offset withFFFF. RETCTX20 overrides the relative count
even in this older global-counter implementation; DTCADJ100 returns the WORD
nonvirtual count. Later NEWXX guards are not an oracle for these paths.

Partial construction is unwound in reverse member,ordinary-base,virtual-base
order. Virtual-base offsets retain the object's segment. Near pointer values
and near virtual tables use DS; FARPTR80 and FAR_VPTR1000 select actual far loads.
The RTTI path adjusts the object by the virtual-table displacement and returns
the true far type through an SS-relative pointer. Array cleanup preserves32-bit
division/multiplication and16-bit address wrapping. Allocation cookies and the
distinct scalar/array delete callbacks retain their target offsets and masks.

Two differences from the later reference are preserved deliberately. The DOS
member loop reuses the search's element count while walking previous members;
it does not recompute that count on each backward step. After virtual-destructor
address adjustment,the DOS cleanup keeps the pre-adjustment allocation pointer
for release. It also calls the default delete operators only on its far-pointer
paths. No defensive null checks or revised cleanup behavior are introduced.
