# Kana BOSS: four native terminal attack guards

The historical after1189 code expressed the four full Kana attack
controllers as unfinished-frame early returns: accelerating ring,
three-stage ring with its sixteen-pellet middle burst, random cloud,
and rotating ring. The warning and release frames keep
their original short-circuit returns; no projectile, RNG or sound call is
moved across a phase boundary. The rotating ring's AL-mediated signed angle
selection remains untouched because earlier native trials showed that a
C++ `switch` changes the instruction stream.

Scoped original TC4/TLINK stages `af1189a` (acceleration), `af1189b`
(staged), `af1189c` (cloud) and final `af1189d` (rotating) each reproduced
**1,874 CODE bytes**, 274 ordered native fields, nine PUBLIC offsets and
the complete Japanese MAIN image and ordered MZ relocations in both rounds.

## 2026-11-11: current-source staged and rotating launch windows

The staged ring now checks its active launch window with one ordered
conjunction: the frame is at least the first slow release and still
before the last emission cutoff. All three separate releases, the
16-projectile middle pellet volley, speed/angle mutation, warnings and
final state transition remain in their original order. The rotating
ring uses the corresponding positive launch-window conjunction. Its
four-frame volley condition and independent post-turn signed-byte angle
advance remain active only within that window; the historical AL-carried
direction choice remains unchanged.

The accelerating ring and random-cloud families now use positive
post-deadline checks for their terminal SELECT transitions. Cloud and
rotating rings state their unsigned-word zero-remainder cadence directly.
The intro renderer uses a short-circuit early flicker guard for odd
frames before the original deadline. The original one-RNG cloud angle
and signed movement arithmetic are not reassociated.

index before a `while` loop. Each shot still precedes the byte-angle
step, speed increment and signed-index advance. The arrival renderer
also uses a pre-tested signed-index loop, advancing its index before
its byte angle only after each polar/sprite draw. Both preserve their
original 16-bit ABI, local lifetimes and RNG order.
